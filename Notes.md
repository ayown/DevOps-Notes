### Day 1

# OSI Model

## 1. Physical Layer (Text → Bits)

- The job of this layer is **Encoding** — high-level messages are converted into bits using an encoding technique.
- It determines the transmission mode.
- It defines the network topology: Bus, Star, Mesh, Hub & Spoke.

**Devices:** Hub, Spoke, Cables, Wires, Switches

## 2. Data Link Layer (0s & 1s → Frames)

- The converted bits & bytes are very long. If transmitted directly, synchronization problems and error handling become difficult.
- To prevent this, the large sequence is divided into **Frames**.
- If any frame is lost, it is the responsibility of the Data Link Layer to retransmit it.

### Two Sub-Layers

**MAC (Medium Access Control)** — When multiple systems transmit over a shared medium, packet collisions can occur. MAC allows only one system to transmit at a time while blocking the others.

**LLC (Logical Link Control)** — Responsible for communication between the Network Layer and the MAC layer.

**Devices:** Bridges

## 3. Network Layer (Frames + IP Addressing = Packets)

- Decides where the frames should be transmitted.
- Every IP Address has **2 Parts**: Network Part and Host Part.
- Using the Network Part, the destination network is found. Using the Host Part, a particular host inside that network is identified.

### Class Addressing

- Class A → 1 bit reserved
- Class B → 2 bits reserved
- Class C → 3 bits reserved

**Device:** Router | **Protocol:** IP

## 4. Transport Layer (Packets → Segments)

- The Network Layer provides **Node-to-Node Delivery** using IP Addresses.
- Data can reach a specific application only through **Port Numbers**.
- The Transport Layer adds **Application Port Numbers** to provide **Process-to-Process (Point-to-Point) Delivery**.

## 5. Session Layer

A Session is a secure connection established between two systems.

Functions: Authorization, Synchronization

## 6. Presentation Layer

Main Functions: Compression, Encryption, Translation

## 7. Application Layer

Applications generate the data that needs to be transmitted from one system to another.

Common Protocols: HTTP, FTP, SMTP, SSH

# Loopback Address

A loopback address (`127.0.0.1`) is a special reserved IP used by a device to send data packets to itself.

How it works:
- **OS Interception** — instead of sending data to the physical NIC/router, the OS intercepts packets at the IP layer.
- **Internal Rerouting** — the OS redirects the traffic back to the local network software stack.
- **No Physical Network** — data never travels over Wi-Fi, Ethernet or the Internet. You can test apps even when disconnected.

# Substitution Types

In Linux, substitution is the process of replacing something with something else.

- **Brace Substitution** — substitutes the value of a user-defined variable. E.g., `${price}USD`. Can also generate arbitrary sequences.
- **Tilde Expansion** — `~` goes to home directory, `~-` to previous directory, `~+` to current directory.
- **Command Substitution** — executes commands and replaces with their output. Mostly used with system-defined commands.
- **Arithmetic Expansion** — evaluates arithmetic expressions.
- **Word Splitting** — splits results into words.
- **Filename Expansion** — expands wildcards like `*`, `?`.

Regular Expressions are patterns used to search, match and manipulate text in filenames, file contents and script expressions.

| Symbol | Meaning                                    |
|--------|--------------------------------------------|
| `.`    | Matches any single character               |
| `*`    | Matches zero or more occurrences           |

| `[^]`  | Negated character set                      |
| `{}`   | Specifies quantity of characters to match  |

# Cloud Computing

The provision of computing utilities as a service on a **Pay-as-you-go** basis is called Cloud Computing.

Cloud Computing is the on-demand delivery of computing resources such as Servers, Storage, Databases, Networking, Software and Analytics — over the Internet.

Instead of purchasing and maintaining physical servers, users can access these resources whenever required. Organizations that provide Cloud services are called **providers**.

## Traditional IT vs Cloud

| Traditional IT              | Cloud Computing                              |
|-----------------------------|----------------------------------------------|
| Buy own servers             | Rent servers                                 |
| High initial cost           | Pay only for what you use                    |
| Manual scaling              | Easy scaling                                 |
| More maintenance            | Cloud provider manages infrastructure        |

## Why Cloud?

- High Availability
- Scalability
- Reliability
- Cost Effective
- Pay As You Go
- Easy Deployment

## Types of Cloud

### Public Cloud

Services are available over the Internet, managed by a Cloud Service Provider.

Examples: AWS, Microsoft Azure, Google Cloud Platform (GCP)

### Private Cloud

Dedicated cloud for a single organization. More secure with more control over infrastructure.

### Hybrid Cloud

Combination of Public and Private Cloud. Used when some workloads remain on-premises while others run in the cloud.

<hr style="height: 1px; border: none; background-color: #888; margin: 20px 0;" />

Cloud computing has 3 basic business models:

## IaaS (Infrastructure as a Service)

When software is developed and deployed in the Cloud, it can be provided to users on a Pay-as-you-go basis. SaaS delivers software directly to the end user.

# Virtualization

Virtualization is the technology of creating multiple Virtual Machines (VMs) from a single physical machine by sharing hardware resources. It solves the "It works on my machine" problem by providing the same OS, libraries, dependencies and runtime environment on every system.

## Why Virtualization?

- Better Resource Utilization
- Cost Effective
- Easy Backup & Recovery
- Isolation
- Scalability
- Faster Deployment

## Virtual Machine (VM)

A Virtual Machine is a software-based computer that behaves like a physical computer. Each VM has its own Operating System, CPU, RAM, Storage and Applications. Multiple VMs can run on the same physical machine.

## Hypervisor

A Hypervisor is a software layer that creates and manages Virtual Machines by allocating CPU, RAM, Storage and Network resources.

### Type 1 (Bare Metal)

- Runs directly on physical hardware. No host OS required.
- Faster and used in Cloud Data Centers.
- Examples: VMware ESXi, Microsoft Hyper-V, Xen

### Type 2 (Hosted)

- Runs on top of an existing Operating System.
- Easier to install, used on personal computers for learning and development.
- Examples: Oracle VirtualBox, VMware Workstation

## Host OS vs Guest OS

- **Host OS** — the Operating System installed directly on the physical computer (e.g., Windows 11, Ubuntu).
- **Guest OS** — the Operating System installed inside a Virtual Machine.

## Physical Machine vs Virtual Machine

| Physical Machine          | Virtual Machine                |
|---------------------------|--------------------------------|
| Runs directly on hardware | Runs on a Hypervisor           |
| One Operating System      | Multiple Operating Systems     |
| Higher hardware cost      | Better hardware utilization    |
| Difficult to scale        | Easy to create and delete      |

<hr style="height: 1px; border: none; background-color: #888; margin: 20px 0;" />

# Containers

Containers package an application along with its dependencies. They are lightweight, fast, portable and share the host Operating System kernel.

Examples: Docker, Podman

> Docker will be covered separately.

## Virtual Machine vs Container

| Virtual Machine                  | Container                    |
|----------------------------------|------------------------------|
| Uses Hypervisor                  | Uses Docker Engine           |
| Has its own Operating System     | Shares Host OS Kernel        |
| Heavyweight                      | Lightweight                  |
| Large storage requirement        | Small storage requirement    |
| Slow boot time                   | Fast boot time               |
| Better isolation                 | Faster deployment            |

## Similarities

- Both provide isolated environments.
- Both package applications for deployment.
- Both solve dependency-related issues.
- Both are widely used in Cloud Computing and DevOps.

## Interview Questions

**Q1. What is Virtualization?**
Virtualization is the technology of creating multiple Virtual Machines on a single physical machine by sharing hardware resources through a Hypervisor.

**Q2. What is a Hypervisor?**
A Hypervisor is software that creates and manages Virtual Machines by allocating CPU, RAM, Storage and Network resources.

**Q3. Difference between Host OS and Guest OS?**
Host OS runs on the physical machine, whereas Guest OS runs inside a Virtual Machine.

**Q4. What is a Container?**
A Container is a lightweight isolated environment that packages an application and its dependencies while sharing the Host Operating System's kernel.

**Q5. Why are Containers faster than Virtual Machines?**
Containers do not contain a separate Guest Operating System. They share the Host OS kernel, making them lightweight and enabling much faster startup times.

# IAM (Identity and Access Management)

IAM helps create users and assigns privileges to them. Every resource in AWS is given a unique identifier called an **ARN (Amazon Resource Name)**.

Represents an individual user. Each IAM user has its own Username, Password and Access Keys (optional).

Collection of IAM Users. Permissions can be assigned to the entire group.

## IAM Policy

A JSON document that defines permissions (Allow/Deny) for AWS resources. Policies are of two types:

- **Resource-Based Policies** — attached directly to resources such as instances, buckets, volumes, networks, databases.

Inline Policies can be created using the policy manager.

### Policy Template

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "Statement1",
            "Effect": "Allow",
            "Action": [],
            "Resource": []
        }
    ]
}
```

- **Sid** — required when there are multiple statements in a policy.
- **Effect** — Allow or Deny.
- **Action** — specific API operations that are allowed/denied (can use wildcards).
- **Resource** — the AWS resources the action applies to.

## IAM Roles

A role is a secure identity with specific permissions designed to be assumed by trusted entities. Users and Groups have permanent credentials but roles provide **short-term security credentials**.

## Principle of Least Privilege

Always provide only the minimum permissions required to perform a task.

# Networking: Subnetting, VPC, DNS and Web Servers

## Subnetting

Subnetting is the process of dividing a larger network into smaller networks by borrowing bits from the host portion of an IP address. It isolates networks so that smaller public and private networks can be created from a larger network.

## VPC (Virtual Private Cloud)

- A VPC is a logically isolated virtual network inside a public cloud provider's network.
- It lets each customer use a private network that is isolated from other customers, even when they use the same cloud provider.
- A VPC is assigned a CIDR range, which represents its IP address range.
- A VPC can be divided into subnets. Each subnet is associated with a route table.
- A VPC can connect to the internet using an Internet Gateway or, for outbound access from private subnets, a NAT Gateway.
- Public subnets route internet traffic through an Internet Gateway.
- Private subnets can reach the internet through a NAT Gateway without accepting unsolicited inbound connections from the internet.
- Two VPCs can communicate with each other using VPC peering.

### Public and Private Subnets

- Instances in a public subnet can be assigned public IP addresses and can communicate with the internet through an Internet Gateway when the route table permits it.
- Instances in a private subnet do not need public IP addresses. They are not directly reachable from the internet, but can make outbound IPv4 connections through a NAT Gateway.

### Egress-Only Internet Gateway

An egress-only Internet Gateway is a highly available VPC component that allows IPv6 outbound traffic from instances in a VPC to the internet while preventing the internet from initiating IPv6 connections to those instances. It supports IPv6 only; it does not support IPv4.

## DNS

DNS is a directory that maps DNS names to their corresponding IP addresses.

## Web Server

- A web server is a dedicated server that hosts and serves web pages. When a client requests a web page through a browser, the web server returns the requested content.
- A website can be replicated across multiple web servers to improve availability and redundancy.
- Multiple web servers can sit behind a reverse proxy. The reverse proxy accepts client requests and forwards each request to an appropriate web server.
- A reverse proxy can also perform load balancing. Common reverse-proxy web servers include Nginx and Apache HTTP Server.
- With a forward proxy, the destination server sees the proxy's address rather than the client's address, unless client information is forwarded explicitly.
- Web servers behind a reverse proxy commonly communicate with it over private IP addresses.

## Bastion Host

A bastion host is a hardened server placed in a public subnet that provides controlled administrative access, such as SSH, to resources in private subnets. It reduces the need to expose private instances directly to the internet.
